# 对外接口分类目录

本仓对外提供的接口分为三大类。探测时逐类核对，任何一类没有命中都要确认是"确实没有"而非"没找到"。

> 注意：本目录扫描的是**对外接口注册点**（本仓作为服务端暴露给外部调用的入口），不是本仓调用别人的接口（那是消费侧）。仓内模块间的语言级 interface 契约不算对外接口，不纳入。

## 目录

- 一、IDL/契约类接口
- 二、框架路由类接口（HTTP/RPC 入口注册）
- 三、消息/事件订阅类接口
- 易遗漏项

## 一、IDL/契约类接口

以契约文件为准，代码是实现侧。契约与实现必须交叉核对（有契约无实现 = 未落地；有实现无契约 = 自研隐式接口）。

| 类型 | 文件特征 | 提取要点 |
|---|---|---|
| Protocol Buffers | `*.proto` | `service Xxx` 块内的 `rpc Name(Req) returns (Resp)` |
| Thrift | `*.thrift` | `service Xxx { RetType name(1: Type arg) }` |
| OpenAPI/Swagger | `*.yaml/*.json` 含 `openapi:`/`swagger:` | `paths:` 下每个 path + method（get/post/put/delete） |
| GraphQL | `*.graphql/*.gql` | `type Query` / `type Mutation` / `type Subscription` 下的字段 |
| FlatBuffers/Cap'n Proto | `*.fbs`/`*.capnp` | service/rpc 定义 |

注意：IDL 生成的桩代码（`*.pb.go`、`*_grpc.pb.go`、`gen-*/`、`*.pb.cc` 等）不是接口实现，定位实现要找 `RegisterXxxServer` / handler 注册点。

## 二、框架路由类接口

代码中显式注册的 HTTP/RPC 入口。按语言找路由注册点：

| 语言/框架 | 注册模式示例 |
|---|---|
| Go Beego | `beego.Router("/path", &controllers.XxxController{})`、`web.Router(...)`、`beego.NewNamespace(...)`、`beego.Namespace(...)`、`beego.AutoRouter(...)`、`beego.Group(...)`、`RouterGroups` |
| Go gin/echo/chi | `r.GET("/path", handler)`、`e.POST(...)`、`r.Route(...)` |
| Go grpc 服务端 | `pb.RegisterXxxServer(s, &impl{})` |
| Go net/http | `http.HandleFunc("/path", fn)`、`mux.Handle(...)` |
| Java Spring | `@RestController` + `@GetMapping/@PostMapping/@RequestMapping` |
| Java Dubbo | `@DubboService`、`dubbo:service` 配置 |
| Java/C++ 自研 RPC | 服务注册表、`RegisterHandler`、`AddService` 等自有模式 |
| Python FastAPI/Flask/Django | `@app.get("/path")`、`@bp.route(...)`、`urlpatterns` |
| C++ | 自研消息分发表、`MSG_ID -> handler` 映射、宏注册（如 `REG_HANDLER(...)`） |

通信设备/嵌入式类 C/C++ 仓常见**消息分发表**（消息号 + 处理函数表），这类注册表就是接口清单，优先定位。

## 三、消息/事件订阅类接口

异步入口，常被漏掉：

- 消息队列消费：Kafka consumer 订阅的 topic、`@KafkaListener`、RocketMQ `MessageListener`
- 事件订阅/发布：`Subscribe(topic, handler)`、`eventbus.Register(...)`、观察者注册点
- 定时任务入口：`@Scheduled`、cron 注册、`AddFunc("@every 1m", fn)`——无外部请求触发但属于对外提供的服务能力
- 信号/中断处理：嵌入式场景的信号注册、回调挂载点

## 易遗漏项

1. **IDL 生成代码虚增**：把 `*.pb.go` 等桩代码当接口实现统计，虚增数量。排除 gen 目录与生成文件（文件头通常有 `Code generated by ... DO NOT EDIT`）。
2. **同接口多实现**：一个接口多个实现类/多个 handler 版本（v1/v2），只记录一个会漏掉路由选择逻辑。全部列出并标注选择机制。
3. **消息/事件订阅未走显式定义**：异步消费入口没有"路由注册"形式，grep 不到 `GET/POST` 模式，需单独按第三类模式扫描。
4. **宏/表驱动注册**：C/C++ 用宏或数组表注册 handler（如 `CMD_TABLE[]`），单行 grep 模式匹配不到，要定位注册表结构体定义再展开条目。
5. **网关透传**：接口实际由上游网关转发进来，仓内只有 handler 没有路径定义——从 handler 注册点反推接口清单。
6. **Beego 注解路由**：Beego 的 `// ; GET /path` 注解式路由写在 controller 方法上方，grep `beego.Router` 命中不到，需扫注解。
7. **Beego 命名空间嵌套**：`beego.NewNamespace("/v1")` 内嵌套多层 `Namespace`，最终路径需拼接前缀，单看一层会漏路径前缀。
8. **已下线接口**：代码在但路由表/配置中被注释或开关关闭。标注状态（在用/下线），不要直接删除记录。
9. **鉴权中间件挂载点**：鉴权/限流中间件在路由组上挂载（如 `r.Use(AuthMiddleware)`），是接口安全属性的来源，需记录但不单独列为接口。
