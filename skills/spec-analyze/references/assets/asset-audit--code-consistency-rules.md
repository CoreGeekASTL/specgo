# 资产文档代码一致性规则（场景 2 维度二，重点）

适用对象：docs/{arch,biz,tech,qual}/ 下资产文档与索引 README。
核心立场：资产跟着代码走——文档与代码不一致即「失实」，是必须修复的底线问题。所有核验必须真实执行 grep/文件比对，禁止目测通过。只检出不修改：修复走 spec-update，重建走对应 analyze skill。

## 零容忍项（任一命中 → 该篇判「失实」）

### C1 锚点反查

- 提取文档引用的代码证据：文件路径、接口名、结构体/类名、函数名、表名、配置键、常量名。
- 逐条核实：文件路径用文件系统验证存在；标识符在对应文件（或全仓）grep 命中。
- 行号漂移不算失实（代码演进正常），记提示；路径不存在或标识符 grep 零命中 = 失实。
- 抽样口径：每篇至少抽 5 个锚点；不足 5 个的全量核验。

### C2 接口一致性（biz/interface）

- 接口表中的「方法 + 路径」与代码路由注册点（HTTP 路由/RPC service/消息订阅 handler）逐条双向比对：
  - 文档有而代码无 = 失实（捏造或已下线）；
  - 代码有而文档无 = 覆盖缺失（记待修订，提示重跑 biz-interface-analyze）。
- 抽样：接口数 ≤10 全量比对；>10 每功能域至少抽 3 个接口比对。

### C3 数据结构一致性（biz/data-model）

- 文档表名/字段名/字段约束与代码事实比对：建表 SQL（CREATE TABLE）、ORM entity 注册（TableName/RegisterModel）、关键缓存结构体。
- 表不存在、核心字段对不上 = 失实；字段细节（默认值/注释）漂移记提示。
- 抽样：每篇抽 1 个实体全字段比对。

### C4 出站调用一致性（tech/external-call-guidelines）

- 文档声称的下游服务/协议/封装方式与代码实际出站调用点（HTTP client/RPC client stub/MQ 生产端/SDK）抽样比对。
- 文档声称的调用在代码中不存在 = 失实；代码存在文档未登记的下游 = 覆盖缺失。
- 抽样：每外部服务文档抽 2 个调用点反查。

### C6 mermaid 渲染校验

```bash
node <specgo插件目录>/skills/mermaid-validate/scripts/validate-mermaid.mjs <文档>
```

- 文档内全部 mermaid 图 VALID 才算过；任一 INVALID = 失实（图即事实载体，渲染失败等同内容不可信）。

## 非零容忍项

### C5 覆盖留痕

- 文档元信息/说明节应含扫描口径：扫描数、收录数、差集说明或采样口径。
- 缺失不判失实，记「待修订」。

## 计分与分级

- **专项分**：基准 100 扣分制——C1/C2/C3/C4/C6 零容忍命中 -10/处、C5 覆盖缺失 -5/处，下限 0。
- **总分** = 通用分（表达质量，见 asset-expression-rules.md 扣分口径）× 0.4 + 专项分 × 0.6。
- **分级**：总分 ≥95 已基线 / 80–95 待修订 / <80 重写；零容忍命中 ≥3 处直接「重写」。

| 分级 | 处置建议 |
| --- | --- |
| 重写 | 按命中域重跑对应 analyze skill，或走 spec-update 增量刷新 |
| 待修订 | 报告给改进建议，落实到具体章节 |
| 已基线 | 无需动作 |
