# Clean Code 检查规则（27 条 + 语言特则）

> 本规则为 spec-code-check skill 的**内置默认检查依据**，用户未提供外部规范文档时逐条执行。
> 用户提供外部规范文档时，以用户文档为准（可作为本规则的覆盖或补充）。
>
> 结构：**通用 27 条**（语言无关，全量逐条过）+ **语言特则**（按仓内主语言选取对应章节逐条过，其它语言章节跳过）。

| 序号 | 规范维度（代码层面） | 规范要求描述（含必须/禁止） | 可调参数（仅数值） |
| :---: | :--- | :--- | :--- |
| 1 | 命名意图 | 类名、变量名、函数名必须完整揭示其用途和意图，禁止使用拼音、无意义单字母（循环索引 `i`/`j` 除外）及模糊缩写（如 `data`、`temp`） | — |
| 2 | 布尔命名规范 | 布尔类型变量或返回布尔值的函数，必须带有 `is` / `has` / `can` / `should` 等明确语义前缀，禁止使用 `flag` 或 `status` 等无含义命名 | — |
| 3 | 函数规模 | 单个函数（含注释及空行）总行数不得超过设定上限 | 50 |
| 4 | 逻辑复杂度 | 单个函数的圈复杂度（独立路径条数）不得超过设定上限 | 10 |
| 5 | 接口文件规模 | 单个接口定义/头文件总行数不得超过设定上限 | 2000 |
| 6 | 实现文件规模 | 单个实现文件/源文件总行数不得超过设定上限 | 4000 |
| 7 | 代码缩进 | 缩进必须使用空格，且每一级缩进的空格数固定为设定值 | 4 |
| 8 | 变量初始化 | 局部变量必须在声明语句中同时完成初始化，禁止声明与赋值分离 | — |
| 9 | 注释内容哲学 | 注释仅允许解释业务逻辑缘由（Why）或设计约束（Why not），**禁止**复述代码行为（What）；同时禁止保留任何被注释掉的废弃代码 | — |
| 10 | 返回值检查 | 函数返回非空状态值（指针/句柄/错误码）时，调用方必须显式检查，禁止忽略 | — |
| 11 | 异常使用范围 | 异常机制仅限用于不可恢复的致命错误，禁止用于常规业务分支或流程控制 | — |
| 12 | 递归限制 | 禁止不可控递归；若允许递归，最大调用深度不得超过设定值（0 表示完全禁止） | 0 |
| 13 | 魔法数字 | 业务逻辑代码中禁止直接出现 0 / 1 / -1 等字面量（循环计数器除外） | — |
| 14 | 空值检查距离 | 对指针/引用/可空对象解引用或调用前，必须在设定行数内完成非空校验 | 3 |
| 15 | 资源释放后处理 | 动态内存/文件句柄/连接等资源释放后，对应变量必须立即置为无效值（如 `null`） | — |
| 16 | 函数参数个数 | 单个函数的形参数量不得超过设定上限 | 5 |
| 17 | 嵌套深度 | 条件判断（`if`/`else`）与循环（`for`/`while`）相互嵌套的总层数不得超过设定上限 | 4 |
| 18 | 跳转语句（`goto`） | 禁止使用 `goto` 向上跳转；仅允许在单函数内向下跳转至统一错误处理出口 | — |
| 19 | 数组/缓冲区边界 | 对数组或缓冲区进行写入操作时，必须显式校验写入长度不超过容量 | — |
| 20 | 单一职责（模块级） | 单个模块/类的修改原因（职责）不得超过设定个数（1 表示严格单一职责） | 1 |
| 21 | 逻辑抽象层级（SLAP） | 单个函数体内的语句必须处于同一抽象层级，禁止高层业务逻辑与底层实现细节混写 | — |
| 22 | DRY（无重复逻辑） | 禁止在两处及以上位置出现相同的业务逻辑片段，必须抽取为公共函数或工具类 | — |
| 23 | 迪米特法则（方法链） | 禁止连续调用超过设定层数的方法/属性链（如 `a.getB().getC().do()`），避免暴露内部结构 | 2 |
| 24 | 布尔参数传递 | 禁止传递布尔值作为函数参数来切换内部两种不同行为，应拆分为两个独立函数（如 `enableX()` 和 `disableX()`） | — |
| 25 | 命令查询分离（CQS）| 执行写操作（修改状态/命令）的函数**禁止**返回查询结果；执行读操作（查询）的函数**禁止**修改内部状态 | — |
| 26 | 副作用隔离 | 函数体内禁止对外部全局状态（含静态变量、外部文件、数据库）产生非预期的隐蔽副作用 | — |
| 27 | 测试用例命名规范 | 单元测试函数命名必须采用 `should[预期行为]_When[触发条件]` 格式，禁止使用 `test1` / `case2` 等无意义命名 | — |

## 语言/框架惯例冲突的默认豁免判定

以下冲突情形判"豁免"，遵循语言惯例与仓库存量风格，但必须在检查文档中写明冲突双方与判定依据：

| 规则 | 冲突情形 | 默认判定 |
| --- | --- | --- |
| #7 缩进 4 空格 | Go `gofmt` 强制 tab | 豁免，遵循 gofmt 与仓库存量 |
| #27 测试命名 should..._When... | Go testing 强制 `Test` 前缀 | 豁免，遵循 Go 惯例；可建议折中 `TestX_ShouldY_WhenZ`，不强制 |
| #10 返回值检查 | 调用方刻意忽略某返回值（有业务依据，如不同链路统一错误码） | 判"刻意设计"，要求代码补注释说明取舍 |
| #25/26 CQS/副作用 | read-through 缓存的查询带写缓存副作用 | 豁免，业界标准模式，要求注释说明 |
| #15 资源释放后置 null | Go 等 GC 语言无置 nil 惯例 | 豁免，按语言惯例 |
| #13 魔法数字 | 测试断言中的期望值字面量、循环计数器 | 豁免（规则原文已豁免循环计数器） |

## 高发违规区（检查重点提示）

按实际检查经验，以下条目最容易出问题，优先核对：

1. **#2 布尔命名**：返回值/结构体字段布尔缺 `is` 前缀（如 `pass`、`result`、`valid`）
2. **#13 魔法数字**：字段数、页大小、格式长度等字面量未常量化
3. **#22 DRY**：相同拦截/校验代码块在多个入口重复（≥2 处即违规）
4. **#21 SLAP**：高层业务流程中混入 IO 读取/字符串拼接等底层细节
5. **#1 命名意图**：`wl`、`kv`、`tmp`、`data` 类模糊缩写
6. **#10 返回值检查**：`_` 忽略返回值且无注释说明

## 安全附加项（语言无关，随通用 27 条一并检查）

| 编号 | 规范 | 规范要求描述（含必须/禁止） |
| :---: | :--- | :--- |
| S1 | **敏感信息日志** | 日志禁止输出密码/密钥/token/数据库连接串/完整隐私标识；必须定位问题时只输出脱敏片段（如首尾各 3 位） |
| S2 | **硬编码密钥** | 代码禁止硬编码密码/密钥/证书内容；必须从配置/环境变量/密钥管理服务读取 |
| S3 | **注入防护** | SQL 禁止字符串拼接用户输入（用参数化）；命令执行/路径拼接禁止直接使用未校验外部输入 |

> 安全附加项编号 `S1~S3`，与通用规则、语言特则同表混排引用。

# 语言特则

> 按仓内主语言选取对应章节逐条过；仓内多语言时各章节分别覆盖对应文件。
> 语言特则是对通用 27 条的**语言级落地与补强**，编号独立（G=Go，J=Java，P=Python，C=C/C++），检查文档中引用格式如 `G3`、`J2`。

## Go 特则（G1~G10）

| 编号 | 规范 | 规范要求描述（含必须/禁止） |
| :---: | :--- | :--- |
| G1 | **error 处理** | 所有 `error` 返回值必须显式检查，禁止 `_ =` 忽略；错误跨层传递必须 `fmt.Errorf("...: %w", err)` 包装上下文，判定用 `errors.Is/As`，禁止字符串匹配错误内容 |
| G2 | **context 传递** | 跨层/跨 goroutine 调用第一个参数传 `ctx context.Context`，禁止传 `nil`（根处用 `context.Background()`/`context.TODO()`）；禁止把 ctx 存入结构体字段长期持有 |
| G3 | **并发共享保护** | 共享 map/slice/变量必须有 `sync.Mutex/RWMutex` 保护或改用 `sync.Map`，**禁止无锁裸 map 并发读写**（`concurrent map read and map write` 致命）；锁的粒度与持锁调用约定须在注释写明（如"调用方须持有写锁"用 `Locked` 后缀命名） |
| G4 | **goroutine 生命周期** | 启动 goroutine 必须有明确退出机制（ctx.Done/stopChan/WaitGroup），禁止无控制裸 `go`；禁止在 goroutine 内忽略 panic（必要时 recover + 日志） |
| G5 | **defer 资源配对** | 文件/连接/锁/响应体获取成功后立即 `defer` 配对释放，`defer` 必须写在 error 检查**之后**；`defer` 中忽略返回值须显式 `_ =`；**禁止在长循环内堆积 `defer`**（defer 到函数返回才执行，循环内应改显式 Close 或抽子函数） |
| G6 | **单例与包级状态** | 单例初始化必须 `sync.Once` 保护，禁止"判空即建"式裸懒初始化（并发不安全）；包级可写变量须有并发保护说明 |
| G7 | **接口惯例** | 接口在使用方包定义（accept interfaces），实现方加编译期断言 `var _ Iface = &impl{}`；接口方法数克制（≤5），超大接口按使用场景拆分 |
| G8 | **panic 边界** | 库/Service 代码禁止 `panic`，仅 `main`/`init` 不可恢复场景可用；禁止用 panic 做流程控制（对应通用 #11） |
| G9 | **init 与注册** | `init()` 仅用于轻量注册（如 `orm.RegisterModel`、驱动注册），禁止 IO/网络等重逻辑；实体须 `TableName()` + `init()` 注册 + orm tag 完整 |
| G10 | **时间与数值字面量** | 时长必须用 `time.Duration` 乘法表达（`30 * time.Minute`），禁止魔法秒数（`1800`）；时间格式串提取为常量（对应通用 #13 的 Go 落地） |

## Java 特则（J1~J6）

| 编号 | 规范 | 规范要求描述（含必须/禁止） |
| :---: | :--- | :--- |
| J1 | **资源释放** | IO/连接必须用 try-with-resources，禁止裸 `close()` 散落在业务代码中（通用 #15 的 Java 落地） |
| J2 | **Optional** | 禁止 `Optional.get()` 不判空直接调用；禁止 `Optional` 作为字段或参数，仅作返回值 |
| J3 | **equals/hashCode** | 重写 `equals` 必须配对重写 `hashCode`；作为 Map key / Set 元素的类必须二者具备 |
| J4 | **异常链** | 捕获后转抛必须携带原始 cause（`new XxxException("...", e)`），禁止吞异常（空 catch）与丢失堆栈（对应通用 #11） |
| J5 | **并发保护** | 共享可变状态用 `synchronized`/显式锁/`java.util.concurrent` 容器，禁止裸 HashMap 并发读写；单例用枚举或 DCL + volatile |
| J6 | **不可变与空值** | 返回值集合禁止返回 `null`（返回空集合）；配置类/常量类字段 `final`，禁止暴露可变内部状态引用 |

## Python 特则（P1~P5）

| 编号 | 规范 | 规范要求描述（含必须/禁止） |
| :---: | :--- | :--- |
| P1 | **资源释放** | 文件/连接/锁必须用 `with` 上下文管理器，禁止裸 `open()` 不配 `close`（通用 #15 的 Python 落地） |
| P2 | **异常处理** | 禁止裸 `except:` 与 `except Exception: pass` 吞异常；异常捕获必须具体到类型并带日志（对应通用 #11） |
| P3 | **可变默认参数** | 函数默认参数禁止用可变对象（`def f(x=[])`），用 `None` + 函数内初始化 |
| P4 | **全局状态** | 禁止模块级可变全局变量被多函数隐式改写（通用 #26 的 Python 落地）；必须共享时用显式封装（类/闭包/锁） |
| P5 | **类型与命名** | 公共函数带类型注解（入参/返回值）；snake_case 命名，禁止 camelCase 混入 |

## C/C++ 特则（C1~C4）

| 编号 | 规范 | 规范要求描述（含必须/禁止） |
| :---: | :--- | :--- |
| C1 | **RAII 资源管理** | 内存/句柄/锁必须 RAII 封装（智能指针/lock_guard），禁止裸 `new/delete`、`malloc/free` 散落业务代码（通用 #15 的 C++ 落地） |
| C2 | **const 正确性** | 不修改的参数/成员函数必须 `const` 修饰；禁止 `const_cast` 去除 const 后写入 |
| C3 | **缓冲区边界** | 禁止 `strcpy/strcat/sprintf/gets` 等无界函数，用 `snprintf/strncpy` 并显式校验长度（通用 #19 的 C 落地，安全高危区） |
| C4 | **头文件与初始化** | 头文件必须有 include guard / `#pragma once`；变量定义即初始化，禁止未初始化裸声明（通用 #8 强化） |
